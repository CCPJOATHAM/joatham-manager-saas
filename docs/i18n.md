# Interface française et anglaise

Les langues livrées par JOATHAM Manager sont le français (fr) et l'anglais (en). Toute interface nouvelle ou modifiée doit être utilisable dans les deux langues avant sa livraison. Cette règle s'applique à tous les modules, aux formulaires, notifications, emails, confirmations JavaScript et PDF.

Les noms d'entreprises et de personnes, descriptions, observations, messages et autres contenus saisis restent dans leur langue d'origine. Les codes techniques des rôles, statuts, monnaies et interfaces externes restent stables.

Utiliser trans ou blocktranslate dans les templates. Pour une phrase avec compteur, utiliser count et plural dans un seul blocktranslate. Pour une phrase dynamique en Python, traduire la phrase complète avec des paramètres nommés. Utiliser gettext_lazy pour les libellés définis à l'import. Le catalogue JavaScript Django est chargé par includes/javascript_i18n.html. Les textes partagés sont déclarés avec gettext dans static/joatham_dashboard/js/messages.js.

Le choix est conservé dans le profil, la session et le cookie. Une préférence de profil valide prévaut sur une ancienne session. Le catalogue JavaScript utilise la même langue active et son cache est désactivé pour éviter un catalogue d'une autre langue.

Les montants affichés suivent la langue active. Les montants en lettres des factures disposent d'un rendu français et anglais. Ces présentations ne changent ni la valeur stockée ni la monnaie.

## Mise à jour des catalogues

Installer GNU gettext sur le poste de développement. Depuis le venv du projet, exécuter les commandes suivantes après toute modification de texte.

~~~bash
python manage.py makemessages -l fr -l en --no-wrap -i .venv -i env -i .git -i test_project -i 'test*.py'
python manage.py makemessages -d djangojs -l fr -l en --no-wrap -i .venv -i env -i .git -i test_project
python manage.py compilemessages -l fr -l en
python manage.py check_translations --extract
python manage.py test core.tests_i18n
~~~

Relire les nouveaux msgstr et les pluriels, puis commiter les fichiers .po et .mo des deux domaines. Résoudre les entrées fuzzy. Conserver tous les paramètres de formatage. Vérifier les intitulés métier dans leur contexte, particulièrement les notions de caisse, de comptabilité et de formation.

Le workflow de PR vérifie les catalogues et les parcours bilingues sur Ubuntu 22.04, Python 3.14.10 et PostgreSQL 14.24. Il utilise un hachage rapide uniquement pendant les tests. Le workflow s'exécute pour pull_request et ne contient aucune étape de déploiement.

## Vérifications de revue

Tester la page concernée en français puis en anglais, la persistance du choix après reconnexion, les validations et états vides, les confirmations JavaScript et les exports PDF. Vérifier une entreprise et des contenus saisis en français pendant une navigation anglaise, pour confirmer leur conservation.

Le contrôle check_translations signale les catalogues incomplets, les erreurs de compilation des templates, les libellés HTML visibles non marqués et les messages ou libellés Python qu'il peut analyser statiquement. Le contrôle de source ne remplace pas la lecture des écrans et des PDF.
