# Internationalisation JOATHAM Manager

Langues supportees :

- Francais (`fr`, defaut)
- Anglais (`en`)
- Portugais (`pt`)
- Espagnol (`es`)

## Mise a jour des catalogues

Apres avoir ajoute des `gettext_lazy`, `{% trans %}` ou `{% blocktrans %}` :

```powershell
env\Scripts\python.exe manage.py makemessages -l fr -l en -l pt -l es
```

Cette commande est une commande de developpement. En production, ne relancez pas
`makemessages` par defaut si les fichiers `.po` existent deja et ont ete relus.

Relire ensuite les fichiers :

```text
locale/fr/LC_MESSAGES/django.po
locale/en/LC_MESSAGES/django.po
locale/pt/LC_MESSAGES/django.po
locale/es/LC_MESSAGES/django.po
```

## Verification gettext

`compilemessages` exige GNU gettext et son executable `msgfmt`.

Sur Ubuntu :

```bash
if ! command -v msgfmt >/dev/null 2>&1; then
  sudo apt update
  sudo apt install gettext
fi
```

Sur Windows :

```powershell
Get-Command msgfmt
choco install gettext
```

Apres installation Windows, verifier que `msgfmt.exe` est dans le `PATH`.

## Commandes production

Avant de deployer :

```powershell
env\Scripts\python.exe manage.py migrate
env\Scripts\python.exe manage.py compilemessages
env\Scripts\python.exe manage.py check
```

`migrate` applique notamment le champ `preferred_language` sur les utilisateurs.
`compilemessages` compile les catalogues `.po` existants en `.mo`.
`check` valide la configuration Django avant le redemarrage applicatif.

## Comportement attendu

- Un visiteur non connecte conserve son choix dans la session et le cookie Django.
- Un utilisateur connecte conserve son choix dans `User.preferred_language`.
- Si un utilisateur choisit une langue avant connexion, la session est reprise apres connexion puis synchronisee sur son profil.
- En absence de choix explicite, la langue par defaut reste le francais.
